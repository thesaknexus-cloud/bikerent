# BikeMate

BikeMate manages a bike handoff between two authenticated accounts. The owner creates a rental, invites the renter by a unique link, and starts the clock at handoff. The renter accepts the invitation and can see the same timer and rental details, but only the owner can start or end it.

## Architecture and security

- **Frontend:** existing React/Vite app, responsive owner/renter dashboards, 1-second display clock, and 4-second API refresh. Server timestamps are the source of truth; page refreshes do not reset a rental.
- **Backend:** existing Spring Boot API and JWT authentication are retained. The authenticated account is taken from the verified JWT, never an owner ID supplied by the browser.
- **Database:** JPA persistence supports local H2 and PostgreSQL (including a PostgreSQL provider such as Supabase). Rental start/end timestamps are generated by the backend. Row locks serialize start/end and per-bike creation, renters have read-only endpoints, and completed fine values are frozen.
- **Fine:** default is ₹2.50/minute. It accrues proportionally by second and rounds to the nearest paise. Configure `FINE_RATE_PAISE_PER_MINUTE` for a test environment.
- The application uses Spring Security/JWT rather than Supabase Auth/RLS because the repository already has a working authenticated Spring backend. Keep that backend as the only database access path; do not expose database credentials in Vite variables.

## Run locally

Requirements: Java 17+ and Node.js.

1. In `Bike_Back`, run `mvnw.cmd spring-boot:run` (PowerShell) or `./mvnw spring-boot:run` (macOS/Linux). The local default is H2 on port 8080.
2. In `Bike_Front`, run `npm.cmd install` then `npm.cmd run dev` (PowerShell). Open `http://localhost:5173`; Vite proxies `/api` to port 8080.
3. Register two separate accounts with different emails. Sign into the first account, add a bike in **My bikes**, create a rental using the second account's email, then copy the invite link from the owner's dashboard.
4. Open the link in a second browser or phone, sign in as the invited renter, and accept it. Return to the owner account and choose **Start handoff**. Both dashboards update about every four seconds. The renter sees no start/end controls.
5. Wait past the deadline or set `FINE_RATE_PAISE_PER_MINUTE` for a safe test rate. End the rental as the owner; both accounts see the same saved return time and final fine after refresh.

Rental API endpoints are under `/api/rentals`: `POST` create, `POST /join`, `POST /{id}/start`, `POST /{id}/end`, `GET /mine`, and `GET /{id}`. The server rejects renter start/end attempts, unrelated account reads, invalid durations, duplicate active bike sessions, and duplicate completion.

## PostgreSQL and deployment

For PostgreSQL, set `DB_DRIVER=org.postgresql.Driver`, `DB_URL`, `DB_USERNAME`, and `DB_PASSWORD`; set a strong `JWT_SECRET`, `CORS_ORIGIN` to the exact deployed frontend origin, and `DDL_AUTO=update` for initial setup. Keep secrets in the host's environment settings. The SQL schema addition is in `Bike_Back/src/main/resources/db/migration/V2__rental_sessions.sql`; apply it only to an existing schema that has the `users` and `bikes` tables and has not already had JPA create `rental_sessions`.

- **Render:** use the root `render.yaml` Blueprint; set `CORS_ORIGIN` to the Vercel URL. It provisions a PostgreSQL database and the API container. The Blueprint selects Render's Free Postgres plan for a demo; upgrade the database before relying on it for long-term production data because Free Postgres instances are temporary. See [Render's free instance limits](https://render.com/docs/free).
- **Vercel:** import the repository with `Bike_Front` as the Root Directory. Set `VITE_API_URL` to the Render API URL ending in `/api` (for example `https://your-api.onrender.com/api`).
- A Supabase PostgreSQL connection can be used for storage, but authentication and authorization remain in Spring Security. Do not put Supabase service-role or database keys in frontend environment variables.

## Verification

Run `mvnw.cmd test` in `Bike_Back` and `npm.cmd run build` in `Bike_Front`. Tests cover paise arithmetic, early/on-time returns, renter authorization, duplicate ends, duplicate open bike sessions, and invalid duration input.
